## 3. Libraries
- `src/lib/money.ts`: `type Paise = number`; `assertPaise(n)` (safe integer); `rupeesToPaise(r: number|string)`; `applyBps(amount, bps)` with half-up rounding to integer; `sumPaise`. **No formatting** (the UI chat owns `format.ts`). Tests.
- `src/lib/dates.ts`: date-only helpers on `YYYY-MM-DD` strings (avoid TZ bugs): `addInterval(date, interval, count)` with month-end clamping (Jan 31 + 1 month = Feb 28/29; yearly from Feb 29 → Feb 28), `periodEnd(start, interval, count)` = next start − 1 day, `todayIST()`. Tests including month-end and leap years.

## 4. Auth: `src/lib/auth/`
- `password.ts`: `passwordRules` (more than 8 chars, an uppercase, a lowercase, a special char) and `checkPassword(pw) → {ok, failed: RuleId[]}`; tests. The UI will render the same rules as a live checklist, so export rule ids and labels.
- `index.ts`: `betterAuth({ database: drizzleAdapter(db, { provider: "pg", schema }), emailAndPassword: { enabled: true, minPasswordLength: 9, sendResetPassword: sends via `src/server/mail.ts` }, user: { additionalFields: { role: { type: "string", defaultValue: "customer", input: false } } } })`. Enforce `checkPassword` on sign-up and reset via a `hooks.before` middleware (reject with a 400 and the failed rule ids). On sign-up, also create the matching `customers` row (database hook `user.create.after`) for role customer.
- `src/app/api/auth/[...all]/route.ts`: `toNextJsHandler(auth)`.
- `session.ts`: `getSession()` (server), `requireUser()`, `requireRole(...roles)` throwing a typed `ForbiddenError`/redirecting is the caller's choice — export both `requireRole` (throws) and `hasRole(user, ...roles)`. - `src/features/users/actions.ts`: `"use server"` `createStaffUser({name,email,password})` — admin only, creates the user via `auth.api.signUpEmail` (or internal adapter) then sets role `staff`. Test the guard.
